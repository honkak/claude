# 팀 일일업무보고

하이디스크의 공용 파일 1개를 번갈아 편집하던 일일업무보고를 바꿉니다. 팀원은 **각자 동시에 자기 업무만 입력**하고, 팀장은 **엑셀 같은 표로 한눈에** 봅니다. 데이터는 사내 **goodocs 시트**에 저장합니다.

## 1. 왜 만드나

| 지금 (하이디스크 파일 1개) | 바뀐 뒤 |
|---|---|
| 한 명이 편집 중이면 나머지는 대기 | 각자 동시에 입력, 대기 없음 |
| 남의 칸을 실수로 건드릴 수 있음 | 자기 업무만 보이고 자기 것만 수정 |
| 양식이 사람마다 다름 | 항목이 고정되어 취합·비교가 쉬움 |
| 미제출자를 눈으로 찾아야 함 | 미제출자 자동 표시 |

## 2. 구조

```
[내 업무 입력]  ─┐
                 ├─ 저장 어댑터 ── goodocs 시트 (사내, CRUD)
[팀 현황(팀장)] ─┘   js/store-goodocs.js
```

- 설치나 서버 없이 `index.html`을 브라우저로 열면 됩니다. 사내 웹서버나 공유 폴더에 올려 주소만 공유해도 됩니다.
- 화면 코드와 저장소 코드를 분리했습니다. 저장소가 바뀌어도 `store-*.js`만 교체하면 됩니다.

## 3. 데이터 설계: 한 줄에 업무 1건

goodocs 시트 1행(머리글)에 아래 열을 만듭니다.

| 날짜 | 작성자 | 구분 | 업무내용 | 진행률 | 이슈 | 작성시각 | 수정시각 |
|---|---|---|---|---|---|---|---|
| 2026-10-05 | 김민준 | 오늘 | 냉각수 펌프 #3 진동 점검 | 100 | | 2026-10-05T08:20:00Z | … |
| 2026-10-05 | 김민준 | 내일 | 월간 전력 보고서 작성 | | | … | … |

- 사람마다 칸을 나누지 않고 **행을 쌓기 때문에** 여러 명이 동시에 저장해도 서로 덮어쓰지 않습니다.
- `구분`은 `오늘`(오늘 한 일) 또는 `내일`(내일 할 일)입니다.
- 날짜·작성자로 거르면 일간, 주간, 월간 보고를 모두 같은 데이터로 만들 수 있습니다.

## 4. 화면과 기능

**내 업무 입력 (팀원)**
- 작성자를 한 번 고르면 그 PC에 기억됩니다.
- 오늘 한 일(업무, 진행률, 이슈·지원요청)과 내일 할 일을 입력합니다.
- **어제 계획 불러오기**: 직전 근무일에 적은 "내일 할 일"을 오늘 칸으로 가져옵니다.
- 업무 내용에서 `Enter`를 누르면 새 행이 추가되고, `Ctrl+S`로 저장합니다.
- 바뀐 행만 저장합니다 (추가는 Create, 수정은 Update, 삭제는 Delete).
- 지난 날짜는 읽기 전용입니다. `EDIT_PAST_DAYS`로 조정할 수 있습니다.
- 저장하지 않고 다른 날짜나 사람으로 이동하면 확인을 받습니다.

**팀 현황 (팀장)**
- **일간**: 행 번호와 열 문자(A, B, C…)가 붙은 엑셀형 표로, 팀원별로 묶어 보여줍니다.
- **주간**: 팀원 × 월~금 표입니다. 날짜를 누르면 그날의 일간 보기로 이동합니다.
- 요약: 제출 인원, 미제출자 이름, 이슈 건수, 평균 진행률
- 이슈만 보기, 엑셀로 복사(붙여넣기용), CSV 저장, 60초마다 자동 새로고침

## 5. 파일 구성

```
daily-report/
├── index.html            화면
├── css/style.css         디자인 (라이트·다크, 휴대폰 대응)
└── js/
    ├── config.js         ★ 팀 이름, 팀원, 저장소, goodocs 주소·토큰 설정
    ├── util.js           날짜·알림 등 공통 함수
    ├── store-mock.js     예시 저장소 (브라우저에만 저장, 체험용)

    └── app.js            입력·현황 화면 동작
```

## 6. 사내 goodocs 연결 방법

1. **시트 준비**: goodocs에 문서를 만들고, 시트(탭) 이름을 `일일업무`로 정합니다. 1행에 3장의 열 이름을 입력합니다.
2. **설정 입력** (`js/config.js`)
   ```js
   STORE: 'goodocs',
   GOODOCS: {
     ENDPOINT: 'https://사내-goodocs-주소/api/...',
     TOKEN: '발급받은 토큰',
     DOC_ID: '문서 ID',
     SHEET_NAME: '일일업무',
   },
   MEMBERS: ['실제', '팀원', '이름'],
   ```
3. **호출 함수 맞추기** (`js/store-goodocs.js`)
   - 파일 위쪽 주석에 **가정한 API 형식**이 적혀 있습니다. 실제 goodocs API와 다르면 아래 세 곳만 고칩니다.
   - `[1] goodocsRequest`: 사내에 엔드포인트와 토큰을 넣어 호출하는 코드가 있다면 이 함수 본문을 그 코드로 바꿉니다.
   - `[2] COLUMNS`: 시트 열 이름을 바꿨다면 여기를 맞춥니다.
   - `[3] fromRecord / recordsOf` 및 `list/create/update/remove`의 경로: 응답 모양과 URL 경로를 맞춥니다.
4. **확인**: 입력 화면에서 한 건을 저장한 뒤 goodocs 시트에 행이 생기는지, 팀 현황에 보이는지 확인합니다.

### 연결할 때 주의할 점
- **토큰 노출**: 브라우저에서 직접 호출하므로 토큰이 화면 소스에 보입니다. 팀 내부 전용 토큰(해당 시트만 읽기·쓰기 권한)을 쓰시고, 가능하면 사내 프록시를 거치게 하세요.
- **CORS**: 브라우저에서 goodocs API를 직접 부를 수 없다면(CORS 차단), 사내 웹서버에 간단한 중계 API를 두고 `ENDPOINT`를 그 주소로 바꿉니다.
- **작성자 확인**: 지금은 이름을 목록에서 고르는 방식이라 다른 사람 이름으로도 입력할 수 있습니다. goodocs나 사내 SSO에서 로그인 사용자를 알 수 있으면 그 값으로 작성자를 고정하는 것을 권장합니다.
- **조회 필터**: `list`는 `from`, `to`, `author` 조건을 보냅니다. 서버가 필터를 지원하지 않아도 화면에서 다시 거르므로 결과는 맞습니다. 다만 데이터가 쌓이면 느려질 수 있어 서버 필터 지원을 권장합니다.

## 7. 다음 단계 후보

- 로그인 사용자로 작성자 자동 지정
- 마감 시각(예: 17:30) 미제출자 알림
- 주간·월간 보고서 자동 생성 (같은 데이터로 요약)
- 팀장 코멘트 열 추가
