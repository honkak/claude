# 전기기술팀 일일업무보고

전기기술팀 전용 도구입니다. 하이디스크의 공용 파일 1개를 번갈아 편집하던 일일업무보고를 바꿉니다. 구성원은 **각자 동시에 자기 업무만 입력**하고, 팀장은 **엑셀 같은 표로 한눈에** 봅니다. 데이터는 사내 **goodocs 시트**에 저장합니다.

## 1. 왜 만드나

| 지금 (하이디스크 파일 1개) | 바뀐 뒤 |
|---|---|
| 한 명이 편집 중이면 나머지는 대기 | 각자 동시에 입력, 대기 없음 |
| 남의 칸을 실수로 건드릴 수 있음 | 자기 업무만 보이고 자기 것만 수정 |
| 양식이 사람마다 다름 | 항목이 고정되어 취합·비교가 쉬움 |
| 파트별로 다시 정리해야 함 | 파트별로 자동으로 묶여 보임 |

## 2. 구조

```
[내 업무 입력]  ─┐
                 ├─ 저장 어댑터 ── goodocs 시트 (사내, CRUD)
[팀 현황(팀장)] ─┘   js/store-goodocs.js
```

- 설치나 서버 없이 `index.html`을 브라우저로 열면 됩니다. 사내 웹서버나 공유 폴더에 올려 주소만 공유해도 됩니다.
- 화면 코드와 저장소 코드를 분리했습니다. 저장소가 바뀌어도 `store-*.js`만 교체하면 됩니다.

## 3. 데이터 설계: 한 줄에 업무 1건

goodocs 시트 1행(머리글)에 아래 열을 만듭니다.

| 과제번호 | 날짜 | 작성자 | 소속파트 | 제목 | 내용 | 진행율 | 비고 | 담당자 | 수정자 | 작성시각 | 수정시각 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| P1-261005-01 | 2026-10-05 | 김민준 | 1파트 | 변압기 TR-3 절연유 분석<br>- 정기 샘플링 | - 샘플 채취 및 분석 의뢰<br>- DGA 결과… | 70% | 업체 회신 대기 | 김민준, 이서연 | 이서연 | … | … |

- 사람마다 칸을 나누지 않고 **행을 쌓기 때문에** 여러 명이 동시에 저장해도 서로 덮어쓰지 않습니다.
- 구성원이 입력하는 칸은 **소속파트, 제목, 내용, 진행율, 비고, 담당자**입니다.
  - 제목, 내용, 비고는 여러 줄 입력이 가능하고 줄바꿈이 그대로 저장됩니다. 제목은 보통 3~5줄, 내용은 10줄 정도를 예상했습니다.
  - 진행율도 자유입력입니다 (예: `70%`, `완료`, `진행중`). 숫자로 읽히는 값은 팀 현황에 막대로도 표시됩니다.
  - 소속파트는 `config.js`의 `PARTS` 목록(현재 `1파트, 2파트, 3파트, 변전파트`)에서 고릅니다. 파트가 바뀌면 이 목록만 고치면 입력 화면과 팀 현황에 함께 반영됩니다.
  - 담당자는 여러 명을 넣을 수 있습니다. 시트에는 `김민준, 이서연`처럼 쉼표로 이어 저장됩니다. 기본값은 작성자 본인입니다.
- 과제번호, 날짜, 작성자, 수정자, 작성시각, 수정시각은 자동으로 채워집니다.

### 과제번호와 공동 과제 중복 방지
- 과제번호는 **처음 저장할 때** 자동으로 붙습니다. 형식은 `파트코드-등록일-순번`입니다.
  - 예) `P1-261005-01` = 1파트에서 2026-10-05에 첫 번째로 등록한 과제
  - 파트코드는 `config.js`의 `PART_CODES`에서 정합니다 (기본 `1파트=P1, 2파트=P2, 3파트=P3, 변전파트=SS`, 목록에 없는 파트는 `ETC`).
  - 순번은 저장할 때 그날 그 파트에서 이미 쓰인 번호 다음으로 매깁니다. 같은 파트의 두 사람이 정확히 같은 순간에 저장해 번호가 겹치면, 저장 직후 다시 확인해 한쪽에 다음 순번을 붙입니다.
  - 저장 전에는 "새 과제"로 표시됩니다. 번호는 등록 당시의 파트·날짜를 담으므로, 나중에 파트를 바꿔도 번호는 그대로입니다.
- 이월하거나 불러와도 같은 번호를 유지합니다. (끝난 과제를 불러오면 양식만 빌린 새 과제로 보고 새 번호를 붙입니다.)
- **하루에 한 과제번호는 한 줄**만 남깁니다. 공동 과제는 담당자 누구나 그 줄을 수정할 수 있고, 내 입력 화면에도 동료가 올린 공동 과제가 함께 보입니다(번호 아래 "OOO 수정" 표시).
- 오늘 이미 누가 올린 공동 과제는 이월되지 않고, 불러오기로 같은 번호를 두 번 넣을 수도 없습니다.
- **저장하는 순간** 오늘 보고를 다시 읽어 확인합니다.
  - 같은 과제번호를 동료가 먼저 등록했거나, 내가 화면을 연 뒤 동료가 그 줄을 고쳤으면 **비교 창**이 뜹니다.
  - 비교 창에는 항목별로 `내가 쓴 것 | 동료가 쓴 것`이 나란히 나오고, 다른 칸은 색으로 표시됩니다.
  - **내 것으로 반영**: 그 줄을 내 내용으로 덮어씁니다. **동료 것 유지**: 내 내용을 버립니다. **저장 취소**: 아무것도 저장하지 않고 화면으로 돌아갑니다.
  - 내용이 똑같으면 묻지 않고 넘어갑니다.
  - 동료가 그사이 고친 줄을 내가 지우려 하면 지우지 않고 알려 줍니다.
- 한계: goodocs에 "같은 날짜·과제번호는 한 줄" 같은 서버 제약이 없으면, 두 사람이 **같은 순간**에 저장하는 경우까지 완전히 막지는 못합니다. 저장 직전 확인으로 대부분 막힙니다.

## 4. 화면과 기능

**내 업무 입력 (구성원)**
- **이름과 내 소속파트는 크롬에 저장**: 처음 접속하면 어느 탭이든 이름·소속파트 입력 창이 먼저 뜹니다. 한 번 입력하면 브라우저 저장소에 기억되어 다음부터는 묻지 않습니다. 상단 오른쪽의 `작성자 이름 · 파트` 버튼을 누르면 언제든 바꿀 수 있습니다. 다른 PC를 쓰거나 브라우저 데이터를 지우면 다시 입력합니다.
  - 내 소속파트는 이름 옆에서 언제든 바꿀 수 있고, 새 업무의 소속파트 기본값으로 쓰입니다.
  - 담당자 칸에 한 번 쓴 이름도 기억해 두었다가 자동완성으로 보여줍니다.
- 업무마다 한 줄씩 입력합니다. 입력칸은 내용 길이만큼 자동으로 늘어납니다.
- **어제 업무 자동 이월**: 오늘 보고가 비어 있으면, 가장 최근 보고(최대 14일 전까지)에서 **완료되지 않은 업무**를 회색 글자로 띄웁니다.
  - 회색 글자 = 아직 손대지 않은 이월 업무입니다. 내용을 고치면 검은 글자로 바뀝니다.
  - 그대로 저장하면 "어제와 같이 진행 중"으로 오늘 보고에 들어갑니다. 필요 없는 업무는 ×로 지웁니다.
- **완료 버튼**: 누르면 진행율이 `완료`로 바뀌고 초록색으로 표시됩니다. 오늘 보고에는 완료로 남고, **다음 날부터는 이월되지 않습니다.** 다시 누르면 완료가 취소됩니다. 진행율에 `100%`를 직접 입력해도 완료로 봅니다.
- **지난 업무에서 불러오기**: 오래전 내 업무나 팀원의 업무를 검색해서 골라 추가합니다.
  - 누구: 내 업무 / 팀 전체 / 특정 팀원
  - 기간: 최근 1개월 ~ 전체
  - 제목·내용·파트 검색, 여러 건 한꺼번에 선택 가능
  - 같은 업무가 여러 날 반복된 경우 가장 최근 보고 하나만 보입니다.
  - 소속파트·제목·내용만 복사하고, 진행율과 비고는 비워 둡니다.
- **쉬고 있는 내 과제 → 이어서 하기**: 끝나지 않았는데 오늘 목록에 없는 내 과제(최근 `RESUME_LOOKBACK_DAYS`=180일 안)를 업무 목록 아래에 "26일 쉼"처럼 보여줍니다. **[이어서 하기]**를 누르면 마지막 보고의 내용·진행율을 그대로 가져와 **같은 과제번호**로 오늘 목록에 넣고, "재개" 표시가 붙습니다. 자동 이월(14일)이 닿지 않는 20~30일 이상 쉰 과제를 다시 시작할 때 씁니다.
- **지난 업무에서 불러오기**에는 "끝나지 않은 과제만" 필터(기본 켜짐)가 있고, 오늘 목록에 이미 있는 과제는 흐리게 표시되어 다시 고를 수 없습니다. 끝나지 않은 과제를 고르면 마지막 진행율까지 이어서 가져옵니다.
- 새 줄의 소속파트는 저장해 둔 내 파트로, 담당자는 작성자 본인으로 미리 채워집니다.
- 담당자 칸에 이름을 입력하고 `Enter`(또는 쉼표)를 누르면 추가됩니다. 칩의 ×로 뺄 수 있습니다. 팀원 이름은 자동완성으로 뜹니다.
- `Ctrl+S`로 저장합니다. 바뀐 행만 저장합니다 (추가는 Create, 수정은 Update, 삭제는 Delete).
- 지난 날짜는 읽기 전용입니다. `EDIT_PAST_DAYS`로 조정할 수 있습니다.
- 저장하지 않고 다른 날짜로 이동하면 확인을 받습니다.

**팀 현황 (팀장)**
- **일간**: 행 번호와 열 문자(A, B, C…)가 붙은 엑셀형 표입니다. **파트별로 묶어** 보여주고, 컬럼은 `소속파트 | 과제번호 | 제목 | 내용 | 진행율 | 비고 | 담당자 | 최종 수정(시각·수정자)` 순입니다. 여러 줄 입력도 줄바꿈 그대로 보입니다.
- **주간**: 파트 × 월~금 표에 업무 제목 첫 줄, 진행율, 담당자를 보여줍니다. 날짜를 누르면 그날의 일간 보기로 이동합니다.
- 요약: 업무 건수와 작성 인원, 파트별 업무 수, 완료 건수, 보고에 이름이 나온 담당자
  - 모든 담당자가 따로 보고를 쓸 필요는 없습니다. 함께 하는 업무는 한 사람이 쓰고 담당자에 여러 명을 넣으면 됩니다. 그래서 미제출자 표시는 두지 않았습니다.
- **엑셀 내려받기(.xlsx)**: 팀 전체 보고를 엑셀 파일로 내려받습니다.
  - 일간 보기에서는 그날(기본 오늘), 주간 보기에서는 그 주 전체가 대상입니다. 버튼 이름이 "오늘 엑셀 내려받기 / 10/2 엑셀 내려받기 / 이번 주 엑셀 내려받기"로 바뀝니다.
  - 화면의 소속파트 필터와 상관없이 **모든 파트**를 담고, 누르는 순간의 최신 데이터를 다시 읽어 만듭니다.
  - 열: 날짜, 소속파트, 과제번호, 제목, 내용, 진행율, 비고, 담당자, 작성자, 최종 수정, 수정자. 날짜 → 파트 → 담당자 순으로 정렬됩니다.
  - 첫 행 고정, 자동 필터, 열 너비, 줄바꿈이 들어간 칸은 그대로 줄바꿈되어 열립니다. 인쇄는 A4 가로입니다.
  - 파일 이름: `전기기술팀_일일업무보고_2026-10-05.xlsx`
  - 외부 라이브러리 없이 브라우저에서 직접 만들기 때문에 사내망에서도 동작합니다 (`js/xlsx.js`).
- 소속파트 필터, 엑셀로 복사(붙여넣기용), 60초마다 자동 새로고침

## 5. 내 현황 (구성원용)

팀장 대시보드에 문제가 보이기 **전에** 본인이 먼저 확인하고 손볼 수 있는 화면입니다. 팀장 대시보드와 **같은 기준**(`config.js`의 `TASK_RULES`)으로 내 과제(작성했거나 담당자로 들어간 과제)를 계산합니다.

- **먼저 확인할 과제**: 급한 순서로 보여주고, 항목마다 **[오늘 보고에서 업데이트]** 버튼이 있습니다. 누르면 입력 화면의 그 과제로 이동해 진행율 칸에 커서가 갑니다. 오늘 목록에 없으면 마지막 보고를 복사해 넣습니다.
  - **팀장 화면에 정체로 표시 중**: 진행율이 30일(`STALL_DAYS`) 이상 그대로
  - **주의 · N일 후 정체로 표시**: 21일(`WARN_DAYS`)째부터. 팀장 화면에는 아직 안 보이는 단계
  - **N일째 보고 없음**: 끝나지 않은 과제가 7일(`NO_REPORT_DAYS`) 이상 보고되지 않음
- **탭 배지**: 정체·주의 과제가 있으면 "내 현황" 탭에 빨간 숫자가 붙어, 입력 화면에 있어도 알 수 있습니다.
- 요약: 내 진행 중 과제(평균 진행율), 먼저 확인할 과제, 팀장 화면에 정체로 표시 중인 과제, 오늘 보고 저장 여부, 이번 주 완료
- 내 과제 전체 표: 상태(진행 중/주의/정체/완료), 진행율, 최근 보고, 진행율이 그대로인 기간, 정체까지 남은 날
- 저장하면 바로 다시 계산되어, 고친 과제는 목록과 배지에서 사라집니다.
- 이 화면은 일반 화면의 기능(`js/my-status.js`)이라, 팀장 대시보드를 떼어내도 그대로 동작합니다.

## 6. 팀장용 과제관리 대시보드

팀 전체 과제를 과제번호 단위로 모아 지금 상태를 보여주는 화면입니다. 보고 데이터를 **읽기만** 하고 쓰지 않습니다.

- **핵심 숫자**: 진행 중인 과제(평균 진행율), 정체 과제, 이번 주 신규 등록, 이번 주 완료(각각 지난주와 비교)
- **파트별 과제**: 파트마다 진행 중 / 정체 / 기간 내 완료 건수를 누적 막대로
- **주별 신규 등록과 완료**: 최근 N주 동안 주마다 새로 등록된 과제와 완료된 과제
- **담당자별 진행 중 과제**: 사람마다 맡은 과제 수(정체 포함). 공동 과제는 담당자마다 한 건으로 셉니다.
- **과제 목록**: 상태, 과제번호, 파트, 제목, 담당자, 진행율, 등록일, 최근 보고, 진행율이 멈춘 기간. 정체 과제가 맨 위에 옵니다. 행을 누르면 그 과제의 **날짜별 보고 이력**이 뜹니다.
- 기간(4·8·12·26주)과 소속파트로 거를 수 있고, 막대에 마우스를 올리면 값이 보입니다.

판단 기준
- **완료**: 최근 보고의 진행율이 `완료` 또는 `100%`. 완료일은 처음 완료로 보고된 날.
- **정체**: 완료가 아니고, 진행율이 `TASK_RULES.STALL_DAYS`(기본 30일, 달력 기준) 이상 그대로인 과제. 한 달 안에는 정체로 잡지 않습니다. 보고가 끊긴 과제도 30일이 지나면 여기에 들어갑니다.
- **등록일**: 과제번호에 담긴 날짜(`P1-261005-01` → 10/5).

### 일반 화면과 분리하는 방법

대시보드는 `dashboard/` 폴더의 **독립 모듈**입니다. 일반 화면(app.js)은 대시보드를 모르고, 대시보드도 app.js를 쓰지 않습니다. 둘이 함께 쓰는 것은 설정·저장소·데이터 해석 규칙(`js/config.js, util.js, model.js, store-*.js`)뿐입니다. 과제 상태(정체·주의·완료) 판단도 `model.js`에 있어서, '내 현황'과 팀장 대시보드가 항상 같은 결과를 냅니다.

| 하고 싶은 것 | 방법 |
|---|---|
| 일반 화면에서 대시보드 탭만 숨기기 | `config.js`의 `DASHBOARD.TAB_IN_MAIN_APP: false` |
| 일반 화면에서 대시보드를 완전히 빼기 | `index.html`에서 `[팀장용 대시보드]` 표시가 붙은 두 줄(css, js) 삭제 |
| 팀장 전용 페이지로 쓰기 | `dashboard/index.html`을 엽니다 (지금도 바로 사용 가능) |
| 팀장 전용 솔루션으로 옮기기 | `dashboard/` 폴더 + 공통 js 5개(`config, util, model, store-mock, store-goodocs`)를 가져가면 됩니다 |

일반 화면이 바깥 모듈을 탭으로 붙이는 자리는 `DR.registerTab({ id, label, mount, show })` 하나뿐입니다.

## 8. 사내 goodocs 연결 방법

1. **시트 준비**: goodocs에 문서를 만들고, 시트(탭) 이름을 `일일업무`로 정합니다. 1행에 3번 항목의 열 이름 12개를 입력합니다.
2. **설정 입력** (`js/config.js`)
   ```js
   STORE: 'goodocs',
   GOODOCS: {
     ENDPOINT: 'https://사내-goodocs-주소/api/...',
     TOKEN: '발급받은 토큰',
     DOC_ID: '문서 ID',
     SHEET_NAME: '일일업무',
   },
   MEMBERS: ['실제', '팀원', '이름'],
   ```
3. **호출 함수 맞추기** (`js/store-goodocs.js`)
   - 파일 위쪽 주석에 **가정한 API 형식**이 적혀 있습니다. 실제 goodocs API와 다르면 아래 세 곳만 고칩니다.
   - `[1] goodocsRequest`: 사내에 엔드포인트와 토큰을 넣어 호출하는 코드가 있다면 이 함수 본문을 그 코드로 바꿉니다.
   - `[2] COLUMNS`: 시트 열 이름을 바꿨다면 여기를 맞춥니다.
   - `[3] fromRecord / recordsOf` 및 `list/create/update/remove`의 경로: 응답 모양과 URL 경로를 맞춥니다.
4. **확인**: 입력 화면에서 한 건을 저장한 뒤 goodocs 시트에 행이 생기는지, 팀 현황에 보이는지 확인합니다.

### 연결할 때 주의할 점
- **토큰 노출**: 브라우저에서 직접 호출하므로 토큰이 화면 소스에 보입니다. 팀 내부 전용 토큰(해당 시트만 읽기·쓰기 권한)을 쓰시고, 가능하면 사내 프록시를 거치게 하세요.
- **CORS**: 브라우저에서 goodocs API를 직접 부를 수 없다면(CORS 차단), 사내 웹서버에 간단한 중계 API를 두고 `ENDPOINT`를 그 주소로 바꿉니다.
- **작성자 확인**: 지금은 이름을 목록에서 고르는 방식이라 다른 사람 이름으로도 입력할 수 있습니다. goodocs나 사내 SSO에서 로그인 사용자를 알 수 있으면 그 값으로 작성자를 고정하는 것을 권장합니다.
- **조회 필터**: `list`는 `from`, `to`, `author` 조건을 보냅니다. 서버가 필터를 지원하지 않아도 화면에서 다시 거르므로 결과는 맞습니다. 다만 데이터가 쌓이면 느려질 수 있어 서버 필터 지원을 권장합니다.
